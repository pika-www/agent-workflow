## 2026-10-06：结论原文与版本复查

聊天顶栏的 [证据与复查](http://127.0.0.1:18732/evidence) 将具体知识结论与原文片段、行号、归档版本放在一起。逐字匹配只证明片段存在，结论含义仍由用户核对；来源事实与整理者推断分别标注。既有“AI 产品思维”首批官方原文已补 6 条待核对结论，分支和中央分别绑定自己的实际页面版本，不自动批准或改写原知识页。

本地归档核对和公开网页正文比对分别记录。网页变化会保留候选新原文、显示差异及关联页面；后续本地核对或联网失败不能抹掉已发现的变化。核对差异后可采用新原文，随后修订专业分支草稿、重新标注并核对；旧正文、原文、审核版本和替代关系留有记录。已核对的新标注可以明确替代同页旧标注，使旧记录退出待处理队列。中央正式发布继续使用原有审核流程。

普通咨询按当前问题优先保留相关知识，再把预算后实际保留的正文、结论标注与原文片段送入模型。回答下方的读取回执分别展示宿主预读、实际输入及摘录哈希；预算省略的页面、目录中提到的页面不能给模型回答的引用背书。路径匹配仍不代替语义审核。

2026-10-07 的咨询适配使用原生 Agent 工具循环。支持 Responses 的深度报告模型通过 `commentary → function_call → function_call_output → final_answer` 继续同一条执行链，逐项保留原生 `phase`、调用 ID 和模型续跑需要的输出状态。私有报告配置的 `responses_api: true` 开启该路径；缺少原生 phase、流被截断或返回未授权工具时明确失败，不伪造原生中间消息。报告网页读取也由这条循环调用原有深度调研适配器。

本地 Qwen 使用 Chat Completions 的原生 `tool_calls` 和工具结果消息，流式正文与真实工具调用连续处理；该协议没有 Responses 的 `phase`，回执标为 `not_available`。这两条路径均不额外调用模型生成短初答，也不将宿主预读摘录或固定受理文案冒充模型回复。SSE 的 `agent` 事件传递原始可见文本增量、消息标识和工具事件，序号用于重连去重；`reply` 快照用于恢复完整显示。一个问题的中间消息和最终正文更新同一回复区域。原生推理正文不会发送给网页。

2026-10-08 起，原生 Agent 回复以一份连续正文呈现，取消“中间回答”阶段标签与先发回复折叠区。`phase` 继续原样保留在协议记录中，不作为页面标题。提示词不要求固定开场或工具前必先发话，由 Agent 按任务决定回复与调用工具的顺序。校对前被撤回的草稿保留在原始记录中，不重复插入当前正文；旧的非原生历史记录保持原有呈现和数据。

最终正文仍辅助核对识别到的数字、日期、研究结果、定义、能力、因果与时效断言。普通咨询每批最多 6 条、最多 24 条，共用 20 秒核对预算；报告另用原有报告核对预算。超出额度或未完成核对的断言不能作为已核对结论保留。核对模型选择原文片段标识，程序回填逐字引文；不足时局部修正或撤回相关表述，保留先前输出与实际依据。扫描和辅助判定仍可能出错，不改变人工审核。没有知识输入时不能跳过外部事实核对；普通问候与无这些断言的回答不增加核对调用。服务分别记录受理、路由、排队、预读、首段正文、模型调用、核对及完成的耗时和用量；原生中间回答不保证模型首字延迟更短。

专题题集和可重复验收脚本分别为 `tests/fixtures/ai-product-evidence-questions.json`、`scripts/evaluate_topic_evidence.py`；默认只检查原生检索，`--live` 才调用当前模型。每次模型调用使用独立 Wiki 副本，不写聊天历史或正式知识。第一阶段记录见 `outputs/knowledge-evidence-20261006/`，实际输入与回复核对的实现、回归和浏览器记录见 `outputs/answer-verification-20261006/`；后续渐进回应、分批核对、范围限制及真实本地模型纠正记录见 `outputs/progressive-reply-completion-20261006/`。

## 2026-10-06：聊天智能体与知识协作

当前本机网页聊天入口仍为 http://127.0.0.1:18732/。普通聊天使用原有本地模型，明确 @ 专业 Agent 时由该 Agent 直接回复。下面的能力补在现有服务中，不改变 Obsidian 与网页库尚未自动同步的事实。

- 检索结合中文分词、相关术语、命中排序和实际 Wiki 链接。资料不足或用户明确要求补查时，模型可以改写查询再查；这是可追溯的文件检索，目前没有向量嵌入索引。
- 咨询工具只开放本库检索、明确授权的公开网页/搜索和盈利计算。模型决定操作，宿主校验并执行，结果返回模型后再回答；普通咨询最多两次工具操作，报告最多三次。网页、文件和工具结果不能授予新权限，不允许模型借此执行任意终端命令。
- 已确认的长任务执行后会检查覆盖范围。存在可补的缺口时只补一次计划，再检查结果；无法补齐则保留已完成内容与具体缺口，不能标作全面完成。这个模型检查不等于独立事实审计。
- Markdown、TXT、带文字的 PDF 和 Word 可拖入聊天输入区，进入指定专业分支的原始资料。单文件小于5MB，提取正文最多80000字节。相同正文去重，同名更新保留旧版本、原文件哈希和来源；扫描 PDF 需要先做 OCR。网页收录使用 `/收录 公开网址`，正式学习仍通过原来的 `/学习`。
- `/记住 偏好`、`/忘记 偏好`、`/学习进度 内容` 保存独立的用户记忆；偏好不作为事实知识，不会训练模型。不能将密钥和密码存入聊天记忆。
- `/沉淀 方法`、`/沉淀 案例`、`/沉淀 概念` 把上一个真实模型回答保存为待采用经验，保留模型、正文和实际来源；主题重叠只是提醒核对，不能声称已经识别事实冲突。审核后 `/采用 编号` 进入专业 Wiki 草稿；有重叠时需明确“已核对冲突”。草稿产生索引、相关链接和反向链接，保留版本与采用记录；`/回退 编号` 只撤回未发布且未被后续修改的本次采用。
- `/发布经验 编号` 在快照范围一致时发布并排队汇总中央；分支存在其他未审核新增、修改或删除时要求核对完整快照，不能把它们夹带发布。正式知识采用仍沿用现有审核发布边界。也支持“把刚才这轮沉淀为经验”“采用这条经验”“发布这条经验到中央”的自然说法。
- 深度报告已有专用强模型路由、来源补查、计算器回执和 Word/Markdown 下载。本机已按用户选择接入 `https://xhapi.cn/v1` 的 `gpt-5.6-sol`，推理强度为 `high`。真实流式接口验证通过；自己的主 Agent 重新读取 Cephalon 网页并复核此前报告，生成 6772 字答复，Word/Markdown 下载与登记哈希一致，演示计算通过独立算术核对。报告仍是分析草稿，真实成本与市场判断需要补证。密钥仅在 Git 忽略的本机私有配置中保存。该服务的模型列表没有 `gpt-6.1-sol`，实际调用也返回模型不存在。第一轮完整新写被旧 10 分钟上限截断，因此报告预算调整为 20 分钟，普通任务保留 10 分钟。普通聊天仍使用本地模型，报告调用失败不会自动换成 Astra 或本地模型。全网搜索密钥尚未配置，提供公开网址的读取不依赖搜索密钥。接入验证记录在 `outputs/report-model-xhapi-20261006/`。

每个行业和专业分别保存自己的 inbox、Wiki、来源证据和 Agent 配置，共享同一个本地 `qwen3.5:9b` 模型服务。学习更新知识库，不改变模型权重。新增分支会自动出现在 Agent 列表中。

点击顶栏 **主 Agent → 与主 Agent 对话**，直接描述目标。主 Agent 使用模型选择相关的直属行业或模块，并交办具体任务；模块负责人再选择自己的专业子 Agent。每位子 Agent 独立运行原版 OpenWiki、读取自己的知识库，结果先交回模块负责人，再由主 Agent 汇总回复。每轮消息下方可展开实际任务树，查看负责人、任务内容、状态、结果与失败原因。

默认 **主 Agent 自动协作** 无需手选成员。简单问题可以由主 Agent 直接回答；专业任务只交给相关分支，不向全员广播。每个负责人只能交给直属下级，一次最多 4 个下级任务、一轮最多 16 个任务节点，支持现有最多六层分支。本机模型顺序处理任务；聊天与任务树持久化，服务中断会如实标记未完成。

**多 Agent 群聊**和**单独聊天**仍可从新建聊天中选择。手动群聊可选 1 至 8 位行业或专业 Agent，自动补齐上级与中央（最多 24 位）；旧会话保留原来的成员与发言。自动委派目前支持知识查询、分析、方案和文本整理；修改代码、执行部署、发送外部消息等动作需要接入相应执行工具，模型不能把文字方案当作已完成外部操作。

**主 Agent 自主产品分析**：在聊天里发送产品网址并要求拆解或深度分析，系统自动执行公开资料读取、引文核对、分部分析和 Word/Markdown 导出。“只分析、先不做”不会生成开发确认。动态页面使用应用单独启动的无登录 Chrome 浏览器；不连接用户的浏览器会话，不启动应用或付费资源。需要本机 Google Chrome 和 `requirements.txt` 中的 Playwright 依赖。网络请求仍经过公开地址校验、DNS 固定连接与 robots 检查，浏览器不允许提交表单、读取本地文件或 WebSocket；每轮最多读取 8 个页面。来源读取失败时保留错误记录，不把空页面当成已完成调研。

报告正文由当前配置的模型生成，不读取人工补充报告作为答案。模型先提取页面引文，应用核对引文是否存在于本轮实际正文，再分别起草产品与交互、实现与异常处理、市场运营与盈利及知识库项目借鉴，最后由模型依据原文和用户目标自行校对完整报告。引文抽取格式失败会重试；仍失败时仅采用实际原文条目并记录回退来源，不把回退说成模型抽取成功。要求“校对上一份报告”时只采用此前模型生成的报告，不采用人工补充。运行记录保存模型、来源哈希、草稿与校对输出哈希及下载文件哈希，页面显示真实进度。模型自查、引文匹配和章节覆盖不能保证每个解释、推测或利润假设正确。界面与新报告登记将生成结果标为分析草稿，程序检查通过不代表内容已独立核实。引文匹配只证明原文存在，模型对引文的解释不被当成已核实事实。格式错误的表格导出为完整文字，避免丢失内容。源文件与报告保存在 `research-runs/`、`ask-runs/` 和 `reports/`；普通产品分析不会写入或发布正式知识。

页面读回后，报告流程先展示实际原文摘录，再调用模型生成初步回答、分部分析和最终草稿。该摘录说明本轮读取到了什么，仍不证明页面宣传或报告推断正确。普通咨询的分批断言核对与报告自查分别记录，不能把前者的回归结果当作整份报告的独立事实核验。

深度报告可单独配置模型，普通聊天和资料预读继续使用原有 Agent 配置。服务、模型名和密钥保存在 `openwiki-federation/private/report-model.json`，权限为 600；不会复制到 Agent 的 `.env`、问题、来源或报告文件。公开状态见 `/api/agents/report-model`。启用独立报告策略后，如果尚未配置、配置无效或服务调用失败，本轮报告会说明失败，不会回退成本地模型。这个状态不影响普通聊天，也不改变已有报告和知识。配置工具会保留旧配置的私有备份：

```sh
# 原生 OpenAI API 示例；密钥通过本机隐藏输入，不放入命令或聊天。
.venv/bin/python -m federation.report_model --provider openai --model gpt-6.1-sol
# OpenAI 兼容服务示例；模型名和地址必须按所选服务的实际文档填写。
.venv/bin/python -m federation.report_model --provider openai-compatible --model deepseek-v4-pro --base-url https://api.deepseek.com/v1
```

原生服务类型包括 `openai`、`anthropic`、`gemini`；网关使用 `openai-compatible`，支持选择 Responses 协议。配置成功只说明本机保存完成，仍需在主 Agent 发起报告验证服务可用性和内容质量。测试里的模型及 HTTP 服务是受控夹具，不能当成真实强模型报告质量的证据。

**自主联网学习**：在主 Agent 会话勾选“本轮自主联网学习”，或发送 `/学习 让前端 Agent 学习 HTML 表单验证`。无需提供链接：主 Agent 分到模块，模块分到专业成员，专业 Agent 自主生成检索主题，从配置的官方入口发现相关网页，读取正文后使用原版 OpenWiki 更新自己的知识草稿。任务树保留实际查询词、来源网址、内容哈希和知识页变化；主 Agent 最后附上系统核对的执行回执。显式按需学习继续生成待发布草稿；普通对话采用下述默认联网复查模式。默认每个专业最多 2 页，每轮最多 8 页；来源未变且上次成功学习的知识版本未变时跳过重复写库，失败学习可重试。

当前无需搜索服务密钥即可进行官方站点发现；配置 `TAVILY_API_KEY` 后可复用 OpenWiki 已安装的 Tavily 搜索组件。正文提取使用开源 [Trafilatura](https://github.com/adbar/trafilatura)，固定兼容当前 Python 环境的 2.0.0 版本。采集器保留 robots、公开地址、重定向和大小限制；不执行网页脚本。这条按需学习流程生成对应分支草稿，再通过“审核发布”让中央采用，不改变模型权重。

默认对话先获取本地 Wiki 知识，再联网搜索和读取原文，无需用户另说“联网”。遇到差异，核对一手出处、版本、日期及适用条件；网页较新不自动胜出。回答后，已启用的自动复查会独立检查实际本地片段和实际网页正文，确认本地过时后仅替换被证实的片段，保留旧版本、无关内容和事务回读，并同步版本一致的发布副本。证据不足、不同适用条件或并发修改不直接覆盖，按记录补查重试。复查与后台学习共用每日预算，用尽后保留队列次日继续。离线或明确不更新的当轮不进入自动纠错；身份、问候和私有附件本身的处理不强制外查。

聊天和持续行业学习共用实时搜索服务，可在“工具与连接 → 联网搜索”设置。默认自动模式使用 DuckDuckGo，失败或结果不相关时尝试 Bing RSS；已有 Tavily 密钥时优先使用 Tavily。公开搜索无需密钥。发送“请联网搜索……”或 @ 行业 Agent 后提出搜索问题，会实际调用 `web_search`，需要细节时继续读取原文。持续行业学习可发现官方入口清单之外的资料，仍须读取正文并通过核对后才入库。搜索摘要只证明此次取得的搜索结果，不代表正文已经读取或事实已经核验。

**持续行业学习与策略改进（2026-10-09）**：工作台顶栏的“自主学习”打开 `/autonomy`。取得用户持续运行授权后，每位 Agent（包含自建分支）根据自己的职责、已有知识和上次缺口独立选题，读取公开原文、核对逐字引文，再由独立模型调用检查语义、职责相关性与冲突。通过后只将本轮拥有的 `autonomous/` 知识页发布到对应分支与中央，原有草稿不随之发布。来源存档、正文哈希、自动审核记录和实际写入回读均可追溯；自动复核不等同于人工审核，也不保证每项解释正确。发现人工修改、来源不足或冲突时保留候选，轮转到其他成员。

默认每位成员每 24 小时学习一轮、每轮最多 2 份原文；失败后 2 小时重试，全体每日共用 96 次模型调用上限。这是调用次数上限，不是金额上限；调用已有工具模型配置。预算耗尽后次日继续。后台与前台任务共用写入锁，不同时写知识。状态与中断恢复记录保存在 `openwiki-federation/metadata/autonomy/`，暂停可从该页面操作。程序默认关闭，由用户授权后的运行设置开启；电脑睡眠、关机、断网或服务未运行期间无法学习。

代码改进只覆盖 `federation/retrieval.mjs`、`learning-strategy.mjs`、`tool-strategy.mjs` 的纯函数。系统根据实际运行记录提出候选，执行能力检查和 macOS 无网络隔离测试，要求新用例能复现原版本失败、候选通过固定测试和新用例，并通过独立复核后才替换。保留原版本、测试输出与事务记录，替换中断会恢复；人工并发修改不会被覆盖。固定测试、隔离规则、权限和预算不属于自动修改范围。这种升级改变应用的检索、工具选择与学习方法，不训练底层模型权重，也不自动同步 Obsidian 副本。

**聊天协作与正式知识发布是两条独立流程。** 行业负责人可以在群聊中参考专业 Agent 的发言，但其 Wiki 不会自动吸收下级 Wiki。每个知识库仍需独立学习、审核和发布；审核快照直接成为中央的来源。群聊结论、未审核观点和原始资料不会自动写入正式中央知识库。

知识操作流程：**自主采集或手动导入资料 → 对应行业或专业学习 → 审核发布 → 中央汇总**。初始分支只有导航结构，真实知识可以来自子 Agent 自主发现的公开资料，也可以来自你导入的 Markdown/TXT；空库 Agent 可以提供一般建议，但不能假称已有资料。

知识生成与问答继续使用开源 [langchain-ai/openwiki](https://github.com/langchain-ai/openwiki) 原版引擎。`federation/` 提供层级目录、统一网页、串行任务队列、聊天编排与审核发布，未替换上游知识引擎，也未改动上游源码。原版阅读组件与主 CSS 继续复用，图谱渲染器采用开源 [3d-force-graph](https://github.com/vasturiano/3d-force-graph) 1.80.1 和 [Three.js](https://github.com/mrdoob/three.js) 0.186.1；依赖打包到本地 `federation/web/vendor/`，3D 运行依赖无需从外部 CDN 加载。修改渲染源码后，在项目根目录执行 `npm ci --prefix openwiki-tools` 和 `node federation/build-3d.mjs` 重新构建。

# Agent 身份与记忆工作目录

服务器运行目录中的 `openwiki-federation/central/` 和 `openwiki-federation/branches/<id>/` 使用 `IDENTITY.md`、`SOUL.md`、`AGENTS.md`、`USER.md`、`MEMORY.md`、`BOOTSTRAP.md`、`BOOT.md`、`README.md`、`memory/YYYY-MM-DD.md` 与 `skills/<name>/SKILL.md`。源码模板位于 `federation/agent-workspace/`，不会用模板覆盖服务器已有文件。

身份、交流与工作规则在普通对话、身份问答和记忆回顾中实际加载；自主任务也读取对应 Agent 的身份和行为规则。独立的产品分析报告沿用报告提示词，回执明确标记未使用这些工作文件。用户背景按现有个人资料范围控制，明确称呼从当前会话未被遗忘的原文提取，不依赖对话压缩窗口。长期记忆按问题选择，工作日志只引用宿主保存的任务状态与证据。原有个人资料和记忆 JSON 继续管理自动同步区，手工 Markdown 内容保留。

`BOOTSTRAP.md` 的已知步骤在首次初始化执行一次；`BOOT.md` 的已知检查在每次 API 启动执行，不执行文档里的 shell 代码。查看 `GET /api/agent-workspaces/central` 可获得文件、版本与启动回执；每轮模型回执的 `context_usage.workspace` 记录实际提供的文件哈希。编辑方式、优先级和数据边界见 [工作目录说明](federation/agent-workspace/README.md)。

普通问候、身份和称呼问答可以配置单独的模型：通过原有 `PUT /api/tool-services/tool_agent` 设置 `simple_chat_model`，沿用当前对话服务的地址和凭据；空字符串取消模型覆盖。`simple_chat_responses_api` 可单独选择问候协议，`simple_chat_fallback_model` 可配置同一服务的备用模型（使用另一种协议）；其他任务的模型和协议不受影响。复杂问题、记忆回顾、带附件或混合任务继续使用原模型，关闭联网或关闭对话服务时遵守原配置。模型状态 API 会返回两种模型名，每次回复记录实际使用的模型。

所有问候仍实时调用模型，不缓存回答、不使用固定应答。身份、性格、工作约定和称呼仍从当前 Agent 的文件与原会话读取；组合问候必须每个分句都匹配，不能把搜索、执行或附件问题吞掉。问候只预留 256 个输出 token，不重复扫描整个知识库目录，也不为它增加意图判断、事实校对或摘要调用。速度以真实服务回执为准，接口排队和模型服务波动仍可能增加等待。

原生问候请求按需加载模型运行环境，配置的远程模型可直接运行时不加载本地模型框架。工具为空、输入较短且 UTF-8 字节保守上界能放入预算时，跳过分词器初始化；较长的身份文件或其他任务仍走原分词与容量检查。这里只复用代码路径，不复用回答，实际 token 用量仍以模型回执为准。

配置备用问候模型后，主请求 1.2 秒仍无正文便启动备用实时请求；第一条有效正文选定本轮模型并取消另一条路径，不混合两个模型的回答。两条路径使用同一份最新身份、性格、用户与记忆上下文，没有回答缓存。15 秒无正文只显示等待提示，不自动失败；远程问候、身份和称呼问答不受外层任务总时限终止。网络超时、断流、429 和服务端临时错误会按 2、4、8、16、30 秒间隔重连，后续间隔为 30 秒，直到收到完整回答或用户点击“停止等待”。认证和配置错误仍明确报错，普通任务、附件和报告保持原有预算。最多两条路径同时请求，上游重试与取消仍可能计费，回执保留实际调用次数，不把未知用量填为零。已经输出的正文遵守原有完整性校验，同一模型断流后重试时替换未完成片段。纯离线路径保持原配置，不因远程失败自动切入慢速本地模型。

短问候的 HTTPS 连接优先解析 IPv4，避开部分环境中双栈解析的等待；没有 IPv4 记录时保留系统解析回退。仍使用原域名、系统 DNS 和 TLS 校验，不固定上游 IP，也不改变系统网络设置。

回答完成后，正文下方显示首字和总用时，从服务收到本轮问题开始计时，包含排队、准备和模型等待。计时随消息保存，刷新后可重读；旧消息没有完整计时时显示“未记录”，不把模型内部用时当作整轮用时，也不由时间戳猜测首字。流式回答尚未完成时不展示最终耗时。
